# 迭代优先级

## 已完成的起点

将现用 Research Agent 与 33 个相关 owner/adapter/support skill 纳入独立源码仓库。
保留原安装，建立离线检查、来源说明和作者参与的改进流程。

## 下一轮优先：一条真实任务闭环

选择一份作者愿意评估的章节或方法分析，围绕一个已经观察到的问题做现用/候选
比较。优先评价事实与引用保留、科学问题的清晰度、论证支撑、作者修改负担。
沿用已有评估要求，不新增通用科研评分器。

## 随后：源码与现用安装的可追踪更新

当前失败场景是技能分散在两个安装根目录，直接修改安装后 Git 不会自动记录。
先约定从仓库产生修改、逐文件同步对应安装；实际频繁出现遗漏后，再实现最小
diff/install 工具。无需先重写现用运行时。

## 需要真实需求后推进

| 候选 | 触发需求 | 验收 |
|---|---|---|
| 跨机器路径绑定 | 确定需要第二台机器或独立安装 | 相同任务所需 owner/resources 可解析；原机器不受影响 |
| 小型行为回放 | 出现反复的错误执行顺序或错误完成声明 | 测试真正触发对应工具边界，不能只验证预写事件 |
| 可编辑概念图改进 | 作者给出当前 figure owner 无法完成的图例 | 科学语义正确、对象可编辑、目标尺寸可读 |
| 项目上下文辅助 | 已有 `.agent/` 恢复反复丢失关键决定 | 从现有文件恢复目标和证据，无第二套事实源 |
| plugin 分发/公开发布 | 确定给别人安装使用 | 许可、脱敏、路径、依赖与技能发现均已验证 |

用户明确的产品边界：研究者决定方向，任务按需组合，允许从中间开始；
没有默认从选题一路跑到投稿的流水线。外部项目的复杂度不作为功能目标。
